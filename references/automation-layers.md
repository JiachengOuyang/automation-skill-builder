# 自动化层：先找最稳的那一层

大多数失败的自动化，不是“点不准”，而是**明明有更稳的入口却直接去点界面**。把入口按稳定性分层，从高到低选。

```
L0 配置/文件层   ← 最稳，优先
L1 原生接口      ← CLI / COM / 插件 / 内嵌脚本 / 宏
L2 数据/日志层   ← 直读数据库、日志与产物验收
L3 GUI 自动化    ← 最脆，最后用
```

注意：L2 既是“入口”也是“验收入口”。**L3 点完必须回到 L2 验收**，否则你不知道到底成没成。

## 1. L0：配置/文件层

**适用**：软件的结果或输入是明文/半结构化文件；批量生成、格式转换、参数注入。

**手段**：

- 解析/生成 XML、JSON、INI、CSV、YAML、模板。
- 复制样例工程，只改需要改的字段。
- 用软件的“导入/导出”作为桥：生成它认识的文件，再让它自己处理。
- 改用户级配置，不改安装目录。

**优点**：快、可版本控制、可单元测试、不依赖 UI。

**风险**：

- 私有二进制格式不要硬猜；先让软件“另存为”并 diff。
- 编码/换行/路径敏感；ASCII 工作目录最省事。
- 软件可能校验签名/版本/内部 ID；改完打不开就是越界了。

**验收**：生成文件能被软件打开；关键字段读回一致；数值/字节与预期一致。

## 2. L1：原生接口

**适用**：软件提供 CLI、COM/ActiveX、插件 API、内嵌脚本引擎、宏录制器。

**手段**：

- CLI：先 `--help`，再拿最小样例跑；记录退出码和 stderr。
- COM：`win32com.client.Dispatch("ProgID")`；先枚举对象模型，再写一条最小调用。
- 插件 API：优先用官方 SDK 示例，不要从零猜。
- 内嵌脚本：**先录制一段人工操作**，再照着录制结果改；不要猜命令名/参数。
- 宏：录制 → 编辑 → 重放；确认宏文件扩展名和启动方式。

**优点**：语义正确、速度快、可无人值守。

**风险**：

- 接口可能只覆盖部分功能；缺口仍要 L3。
- 版本间 API 可能变；绑定版本并写清。
- 脚本引擎可能有启动钩子/沙箱/许可限制。
- 宏可能依赖当前界面状态，重放前要复位。

**验收**：接口返回成功不够；用 L2 检查产物（文件、数据库、日志）。

## 3. L2：数据/日志层

**适用**：软件把状态写在数据库/文件/日志里；你需要读结果、做校验、判断是否完成。

**手段**：

- 只读连接数据库；先 dump schema，再找“结果表”。
- 日志跟踪：启动前记录文件列表/大小，操作后看新增行。
- 产物检查：文件存在、大小稳定、magic/结构正确、md5 匹配。
- 后置条件：行数、状态字段、时间戳、特定记录。

**优点**：可重复、可断言、可并行；不依赖界面。

**风险**：

- 表/字段可能是缓存或内部实现，升级会变。
- 同会话缓存可能让“已保存”读不到；必要时重启进程再读。
- 只读连接也可能被软件的文件锁挡住；先复制。
- 日志可能延迟写入/轮转/编码不同。

**验收**：你的断言能区分“成功”和“看起来成功”。例如：不是“弹窗消失了”，而是“结果表新增 1 行且 CALCULATED=1”。

## 4. L3：GUI 自动化

**适用**：没有可用接口，或接口覆盖不到的那一小段。

**手段**：UIA/pywinauto、win32、键盘、剪贴板、截图、模板匹配。

**原则**：

- GUI 只做**扳机**和**缺口**，不做数据搬运。
- 先 dump 控件树、截图、记录窗口标题；再设计定位。
- 定位级联：AutomationId/Name → 标签同行控件 → 行内文字点 → 坐标 → 模板。
- 每次点击前确认前台窗口；点后回读校验。
- 见 `gui-automation.md`。

**风险**：分辨率/DPI/主题/语言/版本/面板布局变化都会让脚本失效；维护成本最高。

**验收**：GUI 动作后必须回到 L2；截图只能证明“点了”，不能证明“成了”。

## 5. 混合模式（推荐）

真实项目里最稳的往往是组合：

| 模式 | 做法 | 例子 |
|---|---|---|
| 扳机 + 验收 | L3 点“开始”，L2 等结果表/文件 | 点击 Calculate，轮询 DB 行数 |
| 文件桥 | L0 生成输入，L1 导入，L2 读结果 | 生成 CSV/STEP，软件导入计算，读导出表 |
| 配置注入 | L0 写配置，L1 启动，L2 验收 | 改 ini 设定参数，启动批处理 |
| 脚本 + 导出 | L1 内嵌脚本跑核心，L2 检查导出 | 宏/插件算完导出 CSV |
| 双通道校验 | L1 算一遍，独立脚本再算一遍 | 数值误差 < 0.1% 才算通过 |

一句话：**入口可以脆，验收必须硬。**

## 6. 选择矩阵

| 软件特征 | 首选 | 备选 | 不建议 |
|---|---|---|---|
| 有完整 CLI/API | L1 | L0 | L3 |
| 有内嵌脚本/宏 | L1（录制优先） | L0/L2 | 从零猜 API |
| 项目是 SQLite/XML/JSON | L2 + L0 | L1 | 用 GUI 读数据 |
| 只有 GUI，标准控件 | L3（UIA） | 键盘 | 坐标硬点 |
| 只有 GUI，Qt/自绘 | L3（win32/键盘/剪贴板） | 模板匹配 | 纯坐标 |
| 有导入/导出文件 | L0 文件桥 | L1 | 逐字段点界面 |
| 长计算/批处理 | L1 + L2 轮询 | L3 扳机 | 固定 sleep |
| 加密狗/在线许可 | 先确认授权 | L3 | 绕过许可 |

## 7. 升级/降级协议

**升级**（从 L3 往 L0/L1 走）的触发条件：

- 同一个 GUI 动作重复三次以上。
- 坐标因分辨率/布局失效两次。
- 需要批量处理 10 个以上对象。
- 需要无人值守/定时运行。

**降级**（从 L1 往 L3 走）的触发条件：

- 接口没有覆盖目标功能。
- 接口文档缺失且录制无法得到命令。
- 接口行为与界面不一致，且无法解释。

**换层规则**：

1. 第一次失败：读错误/日志，针对性修复。
2. 第二次失败：换一种定位或接口，不要重复同一操作。
3. 第三次失败：停下来，记录证据，问用户或重新评估这一层是否可行。

## 8. 反模式

- **“先写点击脚本，跑不通再说”**：应该先侦察数据/接口。
- **“UI 成功弹窗 = 成功”**：应该查后置条件。
- **“把所有步骤都 GUI 化”**：应该只 GUI 化缺口，其余走 L0–L2。
- **“用 sleep 等计算”**：应该轮询可观测状态。
- **“坐标写死，换机器再说”**：应该标签定位 + 校准清单。
- **“接口猜着写”**：应该录制/查文档/最小实验。
- **“失败就重试三次”**：应该记录、换策略、问人。

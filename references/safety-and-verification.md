# 安全护栏与验证

自动化的第一目标不是“跑通”，而是**不把数据弄坏、不给出假成功**。这个文件定义护栏和验收标准。

## 1. 威胁模型

| 风险 | 后果 | 对策 |
|---|---|---|
| 写坏原库/原文件 | 不可恢复的数据丢失 | 只读 + 副本 + 备份 |
| “成功”但结果错 | 交付错误，返工 | 后置条件 + 黄金输出 + 交叉验证 |
| 副作用（发邮件/下单/覆盖） | 对外不可逆 | dry-run + `--yes` + 明确范围 |
| 凭据/许可证泄漏 | 安全/合规问题 | 配置分离 + 日志脱敏 + 不写进 skill |
| 抢焦点/弹窗阻塞 | 用户无法工作 | 只在必要时聚焦，结束恢复 |
| 单实例/文件锁残留 | 下次启动失败 | finally 清理 + 启动前检测 |
| 违反 EULA/授权 | 法律风险 | 开工前确认授权范围 |

## 2. 数据安全护栏

1. **源数据只读**：数据库用只读连接；文件只读打开。SQLite 示例：
   ```python
   con = sqlite3.connect(f"file:{path}?mode=ro", uri=True)
   con.execute("PRAGMA query_only=ON")
   ```
2. **改写先复制**：CLI 默认拒绝写原库，必须 `--copy` 或显式 `--in-place`。
   ```text
   app db query <db>          # 只读
   app db copy <db> --out-dir _app_work/projects
   app calc --db <copy>       # 在副本上算
   ```
3. **备份**：修改前做带时间戳的备份；记录源文件大小/md5/修改时间。
4. **校验和**：交付包写 `SHA256SUMS.txt`；关键产物记录 md5。
5. **唯一输出名**：不要覆盖已有文件；用 `name_<timestamp>` 或 `--replace` 显式覆盖。
6. **幂等**：同一命令重复执行结果一致；重复创建前先查存在，或提供 `--replace`。

## 3. 操作安全护栏

- **dry-run**：所有有副作用的命令先支持 `--dry-run`，打印将执行的动作、输入、输出、目标窗口，不实际执行。
- **`--yes`**：GUI 点击、输入、删除、覆盖、提交，默认拒绝；必须显式确认。被拒绝时退出码 2。
- **范围限制**：只操作 `--db`/`--input` 指定的对象；不要“顺便”处理同目录其他文件。
- **破坏性操作二次确认**：删除、清空、覆盖、上传、发送，要求用户明确说“可以”。
- **不绕过安全机制**：不破解许可、不绕过登录/验证码、不隐藏自动化行为去规避检测。授权不明确时先问用户。
- **凭据**：从环境变量/配置文件读取；不打印、不写日志、不进 skill。

## 4. 工作目录与编码

- 所有产物放项目内 `_<app>_work/`：
  ```text
  _app_work/
    inputs/        # 输入副本
    projects/      # 项目副本
    backups/       # 修改前备份
    logs/          # 运行日志
    screenshots/   # 截图
    failures/      # 失败现场
    output/        # 交付产物
  ```
- **ASCII 工作目录**：旧软件/对话框可能不接受中文路径；在 `_run_<stamp>/` 里跑，最后复制到中文交付目录。
- **编码显式**：
  - 读文件先探测 BOM；写文本明确 `encoding="utf-8"`。
  - 给旧控制台/脚本文件（`.scr`、`.bat`）按系统 ANSI（中文 Windows 常为 GBK）写。
  - 日志统一 UTF-8；终端输出前做编码兜底。
- **路径长度/空格**：必要时用短路径或 8.3 名；引号包住所有路径。

## 5. 退出码

统一用四档，脚本和 CI 都能判断：

| 码 | 含义 | 例子 |
|---|---|---|
| 0 | 成功 | 命令完成且验收通过 |
| 1 | 运行/校验失败 | 计算结果不符、超时、文件缺失 |
| 2 | 用法错误或安全拒绝 | 缺参数、缺 `--yes`、缺 `--copy`、窗口歧义 |
| 3 | 缺依赖/环境不满足 | 没装 GUI 库、没找到软件、许可失败 |

错误信息写 stderr；`--json` 时也输出结构化错误（`{"ok": false, "code": 1, "error": "..."}`）。

## 6. 验证金字塔

从下到上，逐层加码：

1. **语法/依赖**：`py_compile`、import、`--help`、JSON 可解析。
2. **冒烟**：`env check`、`selftest`、启动/关闭、列窗口。
3. **黄金输出**：字节一致、md5、文件大小、结构校验。
4. **后置条件**：数据库行数、状态字段、日志关键字。
5. **交叉验证**：独立算法/第二来源，误差在阈值内。
6. **回归**：同一输入重复跑，结果一致。

**没有第 3–5 层，不要对外说“打通了”。** 只通过第 1–2 层，只能叫“能启动”。

## 7. selftest 设计

`selftest` 是新机器/新会话的第一道门。逐项输出，不要一句“OK”糊弄：

```text
[OK]   Python 3.12.1 (>=3.10)
[OK]   环境变量 APP_HOME=C:\...
[WARN] 屏幕 2560x1440 @150%，与基准 1920x1080 不同，坐标需校准
[OK]   GUI 依赖 pywinauto 0.6.9 / Pillow 13.0.0
[OK]   脚本编译 12/12
[OK]   配置 config.toml 可读
[FAIL] 找不到 app.exe（检查 install_dir）
```

规则：

- 硬失败（缺 exe/缺依赖/脚本编译失败）退出 1；可容忍差异（DPI/分辨率）给 WARN。
- `--json` 输出每项 `{name, status, detail}`。
- 可选检查：打开样例库、读哨兵表、启停一次软件（`--gui`）。
- 检查项要覆盖：Python 版本、路径、配置、依赖、脚本编译、模板/JSON、启动壳、日志目录、磁盘空间。

## 8. 黄金输出

三种强度，按可用性选：

| 强度 | 方法 | 适用 |
|---|---|---|
| 字节级 | 输出文件 md5/sha256 完全一致 | 确定性导出（DXF/CSV/PNG） |
| 结构级 | 行数、字段、顺序、文件大小范围 | 有浮动/时间戳的输出 |
| 数值级 | 关键指标误差 ≤ 阈值（如 0.1%） | 计算结果 |

实践：

- 第一次人工确认正确后，保存基准产物和 md5。
- 回归时比对；不一致时输出差异位置（前 10 行/首个不同字节）。
- 数值断言用 `--expect name=value --tol 0.001`，失败退出 1。
- 不要把含时间戳/路径/随机 ID 的文件做字节比对；先规范化。

## 9. 后置条件

“点完了”不等于“成功了”。每条自动化命令结束时检查：

- 数据库：新增/更新行数、状态字段（`saved=1`、`calculated=1`）、关键数值。
- 文件：存在、大小 > 0、magic/结构正确、修改时间在本次运行内。
- 日志：出现成功关键字，或没有新增 ERROR。
- 进程：目标进程已退出/回到空闲。

把后置条件写成代码，不要靠人看截图。

## 10. 交叉验证

独立来源算一遍，误差在阈值内才算通过：

- 用 Python 独立算法读中间数据，和软件结果比。
- 用第二种导出格式/第二个模块比。
- 用已知样例的官方结果比。
- 记录误差（绝对值/百分比）和阈值；超阈值时打印两侧数值。

例：软件算出的排水量 vs 独立积分，误差 0.024%，阈值 0.1% → PASS。

## 11. 证据日志

每次运行写一份可追溯日志：

```text
_work/logs/run_<timestamp>.log
  [time] command: ...
  [time] inputs: path (size, md5)
  [time] app version / pid / window title
  [time] action: ...
  [time] result: exit code, artifacts (size, md5)
  [time] verification: assertions passed/failed
```

- 日志脱敏：不写密码、许可证、完整用户路径（可写相对路径）。
- 失败时附截图和控件树路径。
- 保留最近 N 次；避免无限增长。

## 12. 三次失败协议

1. **第一次**：读完整错误/日志，找根因，针对性修复。
2. **第二次**：换策略（换定位、换接口、换等待信号），不要重复同一操作。
3. **第三次**：停下来，保存现场，向用户说明尝试过什么、卡在哪、需要什么信息。

重复同样的点击/命令三次，是在浪费时间和数据。
